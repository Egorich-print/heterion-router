# ADR-027 — Единый пул Switchyard: `auto` обслуживает весь живой каталог

- **Статус:** принято 2026-11-16
- **Уточнило:** ADR-011 (миссия), контракт авто-маршрутизации из
  `tests/auto_routing.rs` и `tests/empirical_challenge_m4_1.rs` /
  `m5_1.rs` — курируемая лестница в них не изменилась.

## Контекст

Владелец сформулировал требование так: `auto` должен работать «по принципу
NVIDIA Switchyard, то есть **один пул для всех моделей с автоматическим
выбором под запрос**».

Что фактически было в коде (замер 2026-11-16):

- `auto` и `heterion-router/auto` — **виртуальные** модели. Их обслуживает
  `RoutingBackend::auto_plan()` (`crates/heterion-router-gateway/src/routing.rs`),
  а не комбо из БД: `resolve()` перехватывает `is_auto_model(model)` до
  чтения комбо. Комбо `auto` (`combo-auto-switchyard-2`) и
  `heterion-router/auto` (`combo-auto-switchyard-1`) в таблице `combos`
  существуют, но для маршрутизации мертвы.
- Пул задавался **хардкодом** `DEFAULT_AUTO_CANDIDATES` — семь кандидатов
  (gemini ×4, agentrouter ×2, mistral/codestral).
- Живой каталог при этом — **417 моделей на 41 провайдера** (406 `provider/model`,
  9 комбо, 2 auto). То есть 410 живых моделей в пуле не участвовали: клиент,
  спросивший `auto`, получал один из семи отобранных вручную бэкендов.

Отдельная находка того же замера: `google/gemini-3.6-flash` в конфиге MCode
отвечал **404** `unknown model`, тогда как `gemini/gemini-3.6-flash` отвечал
**200** — провайдер в реестре называется `gemini`, а клиент пишет `google/`.

## Решение

### 1. Пул — это лестница плюс весь живой каталог

`auto_pool()` собирает два слоя:

- **Курируемая лестница** — те самые семь кандидатов, с их базовыми
  приоритетами (300/290/280/200/190/100/90) и своим порядком. Контракт
  эмпирических тестов (`DEFAULT_AUTO_CANDIDATES.len() == 7`, порядок и
  приоритеты) не сломан.
- **Хвост** — **все модели всех провайдеров, у которых есть живой бэкенд**
  (реестр ∩ `backends`). Базовый приоритет хвоста — `AUTO_TAIL_BASE_PRIORITY
  = 50`, то есть ниже третьего яруса. Порядок хвоста детерминирован:
  `(provider id, model id)`.

Источник «живых» — тот же, что у каталога `/v1/models`: `ProviderRegistry`
∩ множество поднятых бэкендов. Ровно тот список, который видит клиент.

### 2. Отбор под запрос — прежний, но для всего пула

Фильтры capability применяются ко всем кандидатам, а не только к семи:

- **vision**: модель без `supports_vision` выбывает из запроса с картинкой;
- **tools**: `ToolSupport::None` и псевдо-tool модели (`morph`, `upstage`)
  выбывают из запроса с инструментами; **веб-исполнители** (`executor: "web"`)
  выбывают тоже — у них `tool_calls` жёстко `None` (`web.rs`), а не
  «поддерживаются плохо»;
- **context**: запрос длиннее окна модели обрезается или модель выбывает.

Формула приоритета прежняя: `effective = base × quality × availability`.
Кулдаун 429, пробация и breaker по-прежнему рулят лестницей; прямой путь
`provider/model` не гейтится.

### 3. Бюджет попыток

`AUTO_MAX_ATTEMPTS = 24` — столько апстрим-вызовов может сделать один
запрос `auto`. Без бюджета запрос обходил бы весь каталог (сотни моделей)
и упирался в четыре минуты таймаута. Бюджет считается по **попыткам**, а не
по кандидатам: кандидат в кулдауне или пробации бюджет не тратит.

### 4. 4xx не штрафует модель

Первая версия штрафовала `404` через `quality_tracker`, и это **сломало
замороженный контракт I-12** («4xx не роняет провайдера и его соседей»):
после двух 404 модель уходила в 15-минутную пробацию и выпадала из лестницы.
Штраф за 404 убран: мёртвые модели остаются в пуле, но не могут съесть
бюджет запроса — запрос всё равно упирается в лимит попыток. Модели, которых
нет на площадке, чистятся правкой реестра (ADR-026 — тот же порядок:
перечень берём с площадки).

### 5. Алиас `google` → `gemini`

Реестр: у провайдера `gemini` алиас `google` вместо бесполезного
self-алиаса `gemini`. Измеренное основание: `google/gemini-3.6-flash` → 404,
`gemini/gemini-3.6-flash` → 200. Идентификатор клиента не должен требовать
перенастройки конфига.

## Последствия

- `auto` перестал быть «семилучниковым»: это теперь единый пул из всех
  живых моделей, и запрос выбирает из него.
- Пул **динамический**: провайдер, отключённый через `PATCH
  /api/connections/{id}` (режим «только бесплатно»), исчезает из пула после
  рестарта шлюза — бэкенды строятся на старте.
- Старые комбо `auto`/`heterion-router/auto` в БД остаются мёртвыми и не
  влияют на маршрутизацию; `resolve()` перехватывает их раньше чтения комбо.
- Контрактные тесты: `crates/heterion-router-gateway/tests/unified_auto_pool.rs`
  (5 тестов) — пул покрывает живой каталог, лестница остаётся сверху,
  веб-исполнители не берут tool-запросы, запрос укладывается в бюджет.
