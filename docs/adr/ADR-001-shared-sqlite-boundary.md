# ADR-001. Граница интеграции JS ↔ Rust — общая схема SQLite

> Дата: 2026-09-18 · Статус: accepted

## Контекст

Исходное приложение OmniRoute — Next.js/Electron на Node. Переписывание
целиком «большим взрывом» означало бы остановку рабочего шлюза на неопределённый
срок. Данные (комбо, подключения провайдеров, ключи, история usage) уже лежали
в одной SQLite (`~/.omniroute/storage.sqlite`), которой пользовался JS-сервер.

## Решение

Совмещать обе реализации на одной БД, пока Rust не покрыл нужную
функциональность. Rust читает таблицы **поименно**, без «SELECT \*», чтобы
лишние колонки, добавленные миграциями Node, не ломали выборки.

Схему по-прежнему ведёт JS-набор миграций (`_omniroute_migrations`). Rust-раннер
применяет только `IF NOT EXISTS` DDL и добавляет недостающие аддитивные колонки
через сверку `PRAGMA table_info` (идемпотентно, на JS-БД — no-op). Никаких
разрушающих изменений с обеих сторон.

## Следствия

- Обе реализации можно запускать одновременно; переключение — вопрос порта.
- Rust обязан переживать колонки и форматы, которых не знает (включая два
  формата timestamp в одной таблице — SQLite и ISO-8601).
- Удаление JS-установки не отменяет это решение: БД остаётся общей точкой
  истины для данных, а схема — совместимой.
