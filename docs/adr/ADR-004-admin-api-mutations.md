# ADR-004. Мутации в admin-API — только то, что шлюз реально обслуживает

> Дата: 2026-09-18 · Статус: accepted

## Контекст

JS-дашборд позволял править почти всё: комбо, подключения, ключи, настройки,
провайдеров, биллинг. У Rust-шлюза источник истины роутинга — БД, и любая
правка может мгновенно влиять на живой трафик. Нужно было решить, что
открывать на запись, а что нет.

## Решение

Открыты только мутации, которые шлюз сам применяет:

- `PATCH /api/combos/{id}` — имя, порядок, видимость, стратегия, список моделей
  (перезапись `data` JSON с сохранением неизвестных ключей и не-модельных
  элементов). Применяется сразу: роутер читает БД на каждый запрос.
- `PATCH /api/connections/{id}` — имя, `is_active`, приоритет. Смена активности
  возвращает `restart_required`: бэкенды строятся при старте.
- Ключи (см. ADR-005).

**Не открыты:** ротация секретов провайдеров и провайдерский OAuth — Rust не
владеет расшифровкой `enc:v1:`. Это осознанный разрыв с JS-паритетом.

Вердикт «обслуживается ли запись» вычисляется той же функцией, что использует
роутер (`combos::dispatch_backend`), поэтому UI и маршрутизация не расходятся.

## Следствия

- Изменения комбо безопасны и мгновенны; изменения активности подключений
  требуют перезапуска (и UI об этом честно сообщает).
- Секреты никогда не сериализуются в admin-API — только признак их наличия.
