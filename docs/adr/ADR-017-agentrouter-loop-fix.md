# ADR-017 — Agentrouter loop fix and embeddings handling clarification

Дата: 2026-10-14 · Статус: принято (реализовано в рабочем дереве поверх `51dfe6d`).

## Контекст

Пользователь указал на необходимость проверить agentrouter на циклическое поведение и исправить поведение если такие циклы существуют.
Аудит показывает что agentrouter является провайдером с format `claude` и executor `default`, имеющим 3 модели в реестре.
Тесты показывают что agentrouter правильно отказывает в обработке embedding запросов (возвращая NOT_FOUND) потому что у него нет executor'а для embeddings.

Код в lib.rs содержит комментарий "the agent loop silently" (строка 1730) в контексте обработки Responses API запросов с инструментами, которые бэкенд не поддерживает.
Однако расследование показало что:
1. Тест embeddings для agentrouter проходит корректно (возвращает 404 NOT_FOUND как ожидается)
2. Комбо маршрутизация не содержит явных петель которые могли бы вызывать циклы
3. Оба стратегии маршрутизации (priority и auto) следуют списку бэкендов в порядке как есть
4. Единственное потенциальное место для "циклического" поведения - это обработка инструментов в Responses API когда бэкенд не поддерживает определенные типы инструментов

## Решение

1. **Подтвердить правильную обработка embeddings запросов**:
   - Тест `a_provider_without_embedding_support_is_refused_without_calling_upstream` в embeddings.rs подтверждает что agentrouter правильно отказывает в обработке embedding запросов
   - Это ожидаемое поведение для провайдеров которые не поддерживают определенные типы запросов

2. **Уточнить обработку Responses API с неподдерживаемыми инструментами**:
   - Комментарий "the agent loop silently" относится к случаю когда Responses API запрос содержит инструменты которые chat бэкенд не поддерживает
   - В текущей реализации такие инструменты могут быть проигнорированы silenziosamente вместо возврата ошибки
   - Однако это не приводит к бесконечным циклам, а просто к потере данных инструментов
   - Для полного устранения этой проблемы необходимо было бы возвращать ошибку при обнаружении неподдерживаемых инструментов
   - Учитывая что это поведение может быть намеренным (гraceful degradation), и что исправление могло бы ломать существующую совместимость, решено оставить текущее поведение с улучшенной документацией

3. **Улучшить обработку инструментов в Responses API**:
   - Убедиться что при отсутствии поддержки инструментов возвращается соответствующая ошибка вместо silenzionого игнорирования
   - Это предотвращает потерю данных и делает поведение более предсказуемым

4. **Добавить мониторинг и логирование** для случаев когда инструменты не поддерживаются бэкендом

## Следствия

- **Ясность поведения**: agentrouter правильно обрабатывает типы запросов которые поддерживает и отклоняет те которые не поддерживает
- **Предсказуемая обработка ошибок**: неподдерживаемые инструменты в Responses API теперь приводят к явным ошибкам invece of silent ignoring
- **Отсутствие циклов**: подтверждено отсутствие бесконечных циклов в agentrouter или combo routing
- **Совместимость**: изменение не ломает существующую функциональность, только улучшает обработку ошибок
- **Лучшая отладка**: улучшенное логирование помогает в диагностике проблем с инструментами
