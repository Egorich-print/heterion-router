# ADR-025 — веб-исполнители: Rust-шлюз поверх браузерной сессии

Дата: 2026-11-15 · Статус: принято (реализуется в рабочем дереве).

## Контекст

В реестре провайдеров есть девять позиций, у которых **нет исполнителя**:
`chatgpt-web`, `chatgpt-web-codex`, `claude-web`, `gemini-web`, `grok-web`,
`kimi-web`, `deepseek-web`, `zai-web`, `blackbox-web`. Формат у них
openai-подобный, но `base_url` указывает не на API, а на веб-приложение
(`https://chatgpt.com/`, `https://claude.ai/`, …). Любой запрос к ним падает в
unserved.

Это не опечатка реестра, а отдельный класс провайдеров: подписка ChatGPT,
Claude, Gemini, Grok, Kimi или DeepSeek даёт доступ к моделям **через
веб-интерфейс**, и никакого API-ключа у неё нет. Выпустить ключ в консоли
невозможно — консоли нет.

У оператора есть рабочие сессии этих веб-приложений. Camoufox (Firefox
158.0.1-beta.41, anti-detect) с постоянным профилем и перенесённой сессией
Vivaldi открывает их как авторизованного пользователя; сессия подтверждена
живыми дашбордами (ChatGPT, Claude, Gemini, Grok, Kimi, DeepSeek, Z.ai,
Blackbox).

Значит, чтобы эти провайдеры стали моделями шлюза, нужен исполнитель,
который **управляет браузером**: вводит промпт, ждёт ответ, снимает текст.

## Решение

### Границы

**Веб-исполнитель — это отдельный бэкенд шлюза, а не новый HTTP-клиент.**
Он реализует существующий трейт `ChatBackend`
(`crates/heterion-router-gateway/src/backend.rs`), поэтому шлюз, роутинг,
комбо, бюджеты, кэш, `call_logs` и usage работают для него без изменений.
Модуль живёт в крейте шлюза рядом с `exa.rs`/`openai.rs`/`claude.rs` — свой
крейт не нужен: трейт `ChatBackend` объявлен в шлюзе, а выносить его в
`core` ради одного исполнителя — лишний рефакторинг.

**Управление браузером — на стороне Python (Camoufox + Playwright), шлюз
говорит с ним по HTTP.** Rust-крейт `chromium`-подобного драйвера для
Camoufox не существует: `playwright` на Rust поднимает собственный Firefox,
а не anti-detect-сборку. Поэтому:

| Слой | Язык | Где лежит | Что делает |
|---|---|---|---|
| `src/web.rs` + `src/web_driver.rs` | Rust | крейт шлюза | трейт `ChatBackend`, разбор ответа, ошибки, attribution |
| `webdriver/server.py` + `webdriver/adapters/*` | Python | вне репозитория, в установке Camoufox | долгоживущий процесс Camoufox, адаптеры страниц, приём промпта |

Python-часть остаётся вне репозитория вместе с остальным инструментарием
Camoufox: она работает с профилем оператора, а не с кодом шлюза, и в git
не попадает.

Связь — локальный HTTP на `127.0.0.1` (порт драйвера, не 20128), по
образцу desktop-sidecar (ADR-007): шлюз обращается к драйверу, адрес —
в `HETERION_WEB_DRIVER_URL` (по умолчанию `http://127.0.0.1:20130`).

### Реестр

Веб-провайдеры получают `executor: "web"` и `auth_type: "none"`: ключа у них
нет, и выдумывать его нельзя. Их имена в реестре
(`chatgpt-web`, `claude-web`, `gemini-web`, `grok-web`, `kimi-web`,
`deepseek-web`, `zai-web`, `blackbox-web`, `chatgpt-web-codex`) определяют,
**какой** адаптер в драйвере используется; `executor` определяет, **каким**
исполнителем шлюз их обслуживает.

### Контракт драйвера

```
GET  /health     → {"ok": true, "browser": "camoufox", "version": "..."}
GET  /session    → {"providers": {"chatgpt-web": "logged_in" | "expired" | "unknown"}}
POST /chat       → {"provider": "...", "model": "...", "messages": [...]}
                 → {"text": "...", "finished": true, "usage": null}
                 → 4xx {"error": "not_logged_in" | "needs_operator" | "selector_miss" | "upstream_error"}
```

### Правила честности

Эти правила — смысл подсистемы, а не деталь:

1. **Usage не выдумывается.** Веб-интерфейсы не отдают счётчики токенов
   надёжно; там, где их нет, `usage` = `null`, а не ноль. Как у Exa
   (ADR-019): тарификация веб-подписки неизвестна — cost-заголовок
   остаётся выключенным.
2. **Стриминг честно одночанковый.** Веб-UI отдаёт готовый текст; поток
   эмулируется одним дельта-чанком с `finish_reason: "stop"`. Никакого
   псевдо-стриминга «по кусочкам» с задержкой.
3. **Ошибки различаются.** `not_logged_in` (сессия истекла) и
   `needs_operator` (нужен 2FA/капча/ручной вход) — это разные вещи, и
   клиент должен видеть их разными, иначе агент будет «чинить» то, что
   чинится входом в браузере.
4. **Обход CAPTCHA/2FA автоматически запрещён.** Драйвер сообщает
   `needs_operator` и ждёт, пока оператор введёт код в окне Camoufox.
5. **Только своя сессия.** Драйвер работает с профилем оператора и не
   извлекает чужие учётные данные.
6. **Никаких покупок.** Веб-исполнитель не покупает подписки и кредиты:
   пустой баланс — это `upstream_error` с текстом провайдера.

### Адаптеры

Каждый веб-провайдер — адаптер с четырьмя точками:

| Точка | Что | Как ищется |
|---|---|---|
| `input` | поле ввода промпта | `textarea`, `[contenteditable=true]`, `role=textbox` |
| `send` | кнопка отправки | `button[aria-label*=send]`, Enter в поле ввода |
| `answer` | контейнер ответа | последний блок с текстом модели |
| `done` | признак готовности | кнопка «stop» исчезла / текст перестал меняться |

Селекторы хранятся в конфиге адаптера, а не в коде Rust: верстка веб-приложений
меняется чаще, чем меняется шлюз. Несовпадение селекторов — `selector_miss`,
а не «пустой ответ»: пустой ответ у веб-UI означает, что ответа не было,
и это разные диагностики.

### Порядок работы

Вертикальный срез: `chatgpt-web` (самая простая разметка и самый известный
профиль), затем `claude-web` и `gemini-web`; остальные — по мере готовности
адаптеров.

## Следствия

- `chatgpt-web` и остальные становятся полноценными моделями шлюза: они
  доступны напрямую (`provider/model`), в комбо и через `auto`.
- Подписки, которые нельзя «выпустить ключом», становятся частью пула
  провайдеров — без единого нового API-ключа.
- Стоимость подсистемы — хрупкость: верстка веб-приложений меняется без
  предупреждения. Отсюда обязательный `GET /session` (оператор и агент
  видят, что сессия протухла) и проверка адаптера в тесте на реальном
  ответе, а не на «зелёном» HTTP 200.
- Веб-исполнитель **медленный**: ответ занимает секунды, а не миллисекунды.
  Он не годится для hot-path; он годится как fallback для подписки, которую
  больше нечем оплатить.

## Проверка

- `scripts/ci/check.sh` → all green.
- Живая проверка: `chatgpt-web/<model>` через шлюз возвращает текст
  ответа, `usage` = `null`, `finish_reason` = `stop`.
- Проверка честности: при протухшей сессии драйвер отдаёт `not_logged_in`,
  а не пустой ответ 200.

## Аддендум 2026-11-15 — что показала инвентаризация сессий

Инвентаризация Vivaldi-сессии (6404 URL в истории, 1882 cookie по 617
доменам) дала 66 провайдеров реестра с живой сессией: 27 с активным
подключением в роутере (категория A) и 36 только с сессией (категория B).
Из категории B девять — веб-приложения, перечисленные выше.

Проверено фактами, а не догадками:

- API-ключевые провайдеры категории B выпускают ключ обычным путём
  (ai21 — UUID, minimax — `sk-api-…`, dahl — 64 hex, novita, bazaarlink,
  cloudflare, cerebras, mistral, z.ai); собранные ключи пишутся в роутер
  через admin-API.
- Вход в консоли, где сессии не было, делается через Google-аккаунт
  оператора: выбор аккаунта на плитке, согласие, онбординг. Всё это —
  собственная учётная запись оператора, без обхода 2FA.
- Три провайдера категории A (upstage, cline, xai) после выпуска ключа
  отвечают 403/402 «нет кредитов» — ключи **валидны**, не хватает денег на
  стороне оператора. Это решение владельца, не техническая задача.
- `kilo-gateway` оказался `auth_type: optional`: провайдер отвечает 200 без
  заголовка Authorization, но отвергает **любой** bearer, даже валидный.
  Устаревший токен в роутере ломал запрос — подключение заменено на
  keyless, проверено живым вызовом.

## Аддендум 2026-11-15 — регистрация только по списку адаптеров

Первая версия регистрировала веб-бэкенды по признаку `executor: "web"` в
реестре, если драйвер отвечает на `/health`. Это оказалось неверно: в реестре
девять веб-провайдеров, а адаптеров (кода, который знает композер и место
ответа) — шесть. Провайдер без адаптера попадал в каталог и падал на каждом
запросе.

Решение: драйвер отвечает `GET /providers` списком провайдеров, для которых у
него есть адаптер, а шлюз регистрирует только их
(`web::registrable_providers`, `web_driver::driver_providers`). Провайдер без
адаптера не регистрируется и логируется отдельным предупреждением — в
каталоге его нет.

Факты по состоянию на 2026-11-15 (живые ответы через драйвер):

| провайдер | адаптер | живой ответ |
|---|---|---|
| `chatgpt-web` | есть | да |
| `claude-web` | есть | да |
| `gemini-web` | есть | да |
| `grok-web` | есть | да |
| `zai-web` | есть | да |
| `kimi-web` | есть | да (после входа через Google) |
| `deepseek-web` | нет | сессии нет (вход через Google не завершается) |
| `blackbox-web` | нет | сайт сменился на корпоративный, чата нет |
| `chatgpt-web-codex` | нет | для аккаунта Free раздел Codex недоступен |

Уроки, которые стоит помнить при правке адаптеров:

- **Ответ не ищется по текстовым меткам.** Страница следует локали
  браузера: в одном прогоне «ChatGPT said:», в другом «ChatGPT a dit :».
  Селекторы — классы и атрибуты.
- **Композер тоже попадает под «ответ».** У Claude поле ввода несёт класс
  `prose`, у Z.ai сообщение пользователя рендерится как `markdown-prose`.
  Fallback на общий класс возвращает поле ввода или эхо промпта — лучше
  ждать, чем вернуть не то.
- **Провал клика по композеру не фатален.** На Grok textarea перекрыта
  полупрозрачным слоем: `click` уходит в таймаут, а `fill` работает.
- **В Kimi ввод открывает модалку входа**, и она перехватывает кнопку
  отправки: модалку надо гасить между набором и отправкой.
- **В профиле остаётся незаконченный черновик** — редактор Kimi переживает
  перезапуск сессии, и промпт уходит с чужим текстом впереди, если его не
  очистить.

### Локаль браузера закреплена

С одним только `geoip` Camoufox выбирает язык интерфейса заново при каждом
запуске (de/fr/en/ru/zh), и подпись кнопки в дашборде становится
непредсказуемой: «Neuer Schlüssel» в одном прогоне и «Nouvelle clé» в
следующем. Это ломало автоматизацию сильнее прочих мелочей, поэтому локаль
закреплена (`locale: "de-DE"` в `scripts/cf.py`) — это же делает профиль
похожим на реального пользователя. Адаптеры и рецепты под ключи держат
несколько вариантов подписи на случай смены языка.
