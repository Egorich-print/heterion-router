# Heterion Router GPUI desktop

The native shell is a Rust app on [gpui](https://gpui.rs) 0.2.2 in
`desktop/gpui` (crate `heterion-router-desktop`, outside the workspace). It
talks to the same admin-API as the web dashboard in `desktop/ui`.

## Before writing any code

Read these three, in this order — they are the ground truth, not memory:

1. `docs/port/GPUI-API-NOTES.md` — verified gpui API facts.
2. `docs/port/GPUI-PORT-SPEC.md` — the view/widget contract and the rules.
3. The gpui source itself:
   `~/.cargo/registry/src/index.crates.io-*/gpui-0.2.2/src/`.
   gpui has no `Button`, no `Input`, no `Table` — only `div` with
   flex/grid styles, `uniform_list`, text and images. If a helper name does
   not resolve, look it up; do not guess.

## The three files that matter

| File | Rule |
|---|---|
| `desktop/gpui/src/api.rs` | The typed contract with the gateway. **Changing it means changing `crates/heterion-router-gateway/src/admin.rs` in the same commit.** |
| `desktop/gpui/src/theme.rs` | The palette, mirrored from `desktop/ui/src/app.css`. Same colors as the web dashboard. |
| `desktop/gpui/src/widgets/` | The shared widgets. gpui has none of its own. |

## Porting a view

1. The Svelte view is the functional spec: `desktop/ui/src/views/<name>.svelte`.
2. Copy the skeleton of a sibling view in `desktop/gpui/src/views/`: a struct
   with `data`/`error`/`loading`, `new(cx)`, `refresh(cx)` and `Render`.
3. Load data through `api::spawn_request` — never block the UI thread:

```rust
let Some(client) = api::session_client(cx) else { return; };
api::spawn_request(
    cx,
    move || client.get_json::<Overview>("/api/overview"),
    |result, view: &mut OverviewView, cx| {
        match result {
            Ok(data) => { view.data = Some(data); view.error = None; }
            Err(error) => {
                view.error = Some(error.to_string());
                crate::app::report_error(cx, &error);   // drops the session on 401/403
            }
        }
        view.loading = false;
        cx.notify();
    },
);
```

4. Mutating the gateway: `client.post_json` / `client.patch_json` with the
   body type from `api.rs`, same `spawn_request` wrapper.
5. Every view must survive an empty payload — no database, no connections, no
   keys. Render an empty state, never panic.

## Writing a widget

- A widget that keeps state needs a unique id: `theme::unique_id("my-widget")`.
  Duplicate ids panic at runtime.
- `on_click` and `overflow_y_scroll` live on `StatefulInteractiveElement`:
  the element must have `.id(...)` first.
- The style helpers are Tailwind-shaped (`p_3`, `gap_2`, `w_full`,
  `rounded_md`, `text_xs`); they are generated by macros, so they are not in
  `styled.rs`. The compiler is the authority.
- `use gpui::prelude::*;` is mandatory — it brings `Styled`,
  `InteractiveElement` and `IntoElement`.

## Secrets

- Never log a key, a token, or part of a secret — not in a log line, not in an
  error message, not in a test fixture.
- The operator key lives in `<data dir>/desktop/operator-key.json` (0600). The
  gateway's database never holds it: `api_keys.key` stores `hash-only:<id>`.
- `POST /api/keys` returns a secret exactly once. Show it once, never store it.

## Verify

```sh
cargo fmt --manifest-path desktop/gpui/Cargo.toml
cargo clippy --manifest-path desktop/gpui/Cargo.toml --all-targets -- -D warnings
cargo test --manifest-path desktop/gpui/Cargo.toml
```

A compile is not a verification — a native GUI can compile and still render
nothing. Look at it:

```sh
desktop/gpui/tools/screenshot.sh launch
desktop/gpui/tools/screenshot.sh shot overview
desktop/gpui/tools/screenshot.sh status
desktop/gpui/tools/screenshot.sh stop
```

The MCP server (`desktop/gpui/tools/mcp/server.js`) exposes the same thing
plus the live gateway state to an agent: `router_health`, `router_request`,
`app_launch`, `app_screenshot`, `app_status`, `app_stop`.

## Gotchas that cost time

- `Context` implements `BorrowMut<App>`, but `&mut Context` also implements
  `BorrowMut<Context>` — `cx.borrow_mut()` is ambiguous. Use
  `api::app_mut(cx)`.
- `Context::read_entity` returns the value directly (`Context::Result<T> = T`),
  not a `Result`.
- `Application` is a struct in gpui 0.2.2, not a trait.
- The default font family is `.SystemUIFont` (macOS `.AppleSystemUIFont`);
  monospace is `SF Mono` with `Menlo` as the fallback.
- `gpui`'s build compiles Metal shaders with `xcrun metal`: Xcode must be
  installed. A cold build of the whole tree is ~2 minutes.

## Windows (win32) platform notes

The desktop shell is macOS-only: gpui's macOS renderer, the Metal shaders
(`xcrun metal`) and the `.app` bundle have no Windows counterpart in this
repository. On Windows the `cargo`/`screenshot.sh` commands above do not
apply — the shell is simply not built there, and CI only parses the sources
(`cargo fmt --manifest-path desktop/gpui/Cargo.toml -- --check`). Everything
in this skill that is about the *code* (the contract, the widgets, the
patterns) remains valid on any platform.
