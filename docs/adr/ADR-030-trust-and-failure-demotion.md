# ADR-030 — Доверие к модели и понижение за провал

- **Статус:** принято 2026-11-16
- **Развивает:** ADR-029 (лестница по возможностям и мягкая ротация) — там
  появилась capability-таблица; здесь — **вторая, эмпирическая** ось
  приоритета и починка поведения при провале.
- **Повод:** живой замер 2026-11-16 (деплой ADR-029 без этого ADR).

## Контекст

После вливания research-данных (284 пары «провайдер/модель») в
`model_capabilities` шесть запросов через `auto` дали:

```
запрос 1: HTTP 200, отдал @cf/qwen/qwen3.8-27b
запрос 2: HTTP 401  (Token is invalid)
запрос 3: HTTP 404  (Not Found)
запрос 4: HTTP 404
запрос 5: HTTP 404
запрос 6: HTTP 200, отдал @cf/qwen/qwen3.8-27b
```

То есть **четыре запроса из шести провалились**. Причина видна в данных:
research говорит, какая модель *существует*, но не говорит, что её
**отдаёт этот провайдер**. Голова лестницы после слияния оказалась полной
моделей с классом `frontier` (360 очков), которых ни одна площадка в этом
каталоге не обслуживает: `pollinations/qwen-large`, `trae/gpt-5.2`,
`siliconflow/Qwen/Qwen3.5-397B-A17B` и подобные. Проверка:

- в топ-50 лестницы по capability-данным успешных ответов в `call_logs`
  было **7**;
- 404 от платформы означает «этого id у меня нет», и по контракту I-12
  такой 4xx **не штрафует модель** — то есть мёртвый кандидат оставался
  первым в каждом следующем запросе, и бюджет попыток (24) съедался
  мёртвыми моделями.

## Решение

### 1. Доверие — вторая ось приоритета

Capability-таблица отвечает «какая модель **есть**». Доверие отвечает
«эта площадка её **отдаёт**». Модель доверенная, когда у роутера есть
доказательство, что она отвечала:

1. `call_logs` со `status = 200` — мы получили хороший ответ именно от
   этой пары «провайдер/модель»;
2. `model_context_overrides` с измеренным `real_context` — площадка
   подтвердила окно модели при зондировании;
3. курируемая лестница `DEFAULT_AUTO_CANDIDATES` — проверена вручную.

Доверенная модель сохраняет полный приоритет из capabilities.
Недоверенная (research есть, доказательств нет) получает приоритет
× `UNTRUSTED_DISCOUNT` (0.1) и тем самым оказывается **ниже любой**
модели, с которой роутер говорил. Модель из пула не исчезает: первый же
её успешный ответ делает её доверенной (`mark_trusted` на успехе), и
дальше она соревнуется на своих capabilities.

Скидка применяется только к приоритетам, **выведенным из research**: у
модели без research-заявки нет и повода для недоверия — её приоритет и так
ручной.

Если доказательств нет вообще (свежая установка, пустой `call_logs`),
скидка не применяется: недоверие относительно, а не абсолютно.

### 2. Провал — временное понижение, а не наказание

Ровно то, что описал владелец: «нестабильная модель уходит вниз по
приоритету временно, сохраняя свой интеллект и свойства». Провалившийся
кандидат получает множитель `AUTO_FAILURE_FACTOR` (0.1) на окно
`AUTO_FAILURE_COOLDOWN_SECS` (120 с) — вдвое длиннее окна ротации.

Это **не** штраф quality-трекера:

- 4xx не роняет модель в 15-минутную пробацию (контракт I-12);
- 4xx не роняет провайдера и не трогает его соседние модели;
- модель остаётся в пуле со всеми capabilities и возвращается, когда
  окно истекло.

Действует на 400/401/404/422 (кандидат сам по себе не годится) и на 5xx
(модель или площадка сломаны). 429 не трогается — там уже есть
модельный cooldown, 402/403 — провайдерный.

### 3. Слой ротации и слой доверия — раздельно

Ротация (ADR-029 §3) отвечает «кто отвечает сейчас», доверие — «кому
можно доверять». Обе включаются независимо:

| слой | что делает | переключатель |
|---|---|---|
| capabilities | приоритет по возможностям | таблица `model_capabilities` |
| доверие | скидка недоказанным моделям | `with_trust(store)` |
| ротация | размазывание трафика + понижение за провал | `with_rotation(on)` |

В шлюзе включены все три. Контракты, фиксирующие порядок лестницы,
выключают ротацию явно (`with_rotation(false)`), потому что «модель,
которая только что ответила» по определению уезжает вниз.

## Последствия

- Capability-таблица больше не может вытолкнуть в голову лестницы модель,
  которую площадка не обслуживает: доказательство важнее описания.
- Провал модели больше не повторяется в каждом следующем запросе: после
  первого провала кандидат уходит вниз на 120 с и возвращается.
- Доверие растёт с использованием: чем больше роутер говорит с моделью,
  тем выше её место. Новые модели входят в оборот постепенно, а не сразу.
- `call_logs` стал частью входных данных роутера: чистка логов убирает
  доверие, и модели снова становятся «недоказанными» (скидка вернётся).
