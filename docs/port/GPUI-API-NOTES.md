# GPUI 0.2.2 — verified API notes

Everything below was read out of the crate source on this machine, not from
memory. **The source is the ground truth** — when in doubt, open it:

```sh
ls ~/.cargo/registry/src/index.crates.io-*/gpui-0.2.2/src/
```

Facts that are easy to get wrong:

| Fact | Value |
|---|---|
| Crate | `gpui = "0.2.2"` (crates.io), edition 2024, no `rust-version` cap |
| Features | `default-features = false, features = ["font-kit"]` is enough on macOS |
| Renderer | without `macos-blade`: gpui's own Metal renderer, shaders compiled at build time by `xcrun metal` (needs Xcode) |
| Fonts | macOS system fonts — the default family is `.SystemUIFont` → `.AppleSystemUIFont`. **No font files needed.** |
| Build time | cold build of the whole gpui tree: ~2 min on this machine |
| Rust | builds on stable 1.99.0 |

`font-kit` **must** be enabled: the macOS text system module is behind
`#[cfg(feature = "font-kit")]`.

## Bootstrap

```rust
use gpui::{App, Application, TitlebarOptions, WindowOptions};

Application::new().run(move |cx: &mut App| {
    cx.open_window(
        WindowOptions {
            window_bounds: Some(gpui::WindowBounds::Windowed(
                gpui::Bounds::centered(None, gpui::size(gpui::px(1280.0), gpui::px(860.0)), cx),
            )),
            titlebar: Some(TitlebarOptions {
                title: Some("Heterion Router".into()),
                appears_transparent: false,
                traffic_light_position: None,
            }),
            app_id: Some("com.heterion.router".into()),
            ..Default::default()
        },
        |_window, cx| cx.new(|cx| MyView::new(cx)),
    )
    .ok();
    cx.activate(true);
});
```

`Application` is a **struct** in 0.2.2, not a trait.

## Styles

`use gpui::prelude::*;` brings `Styled`, `IntoElement` and `InteractiveElement`
into scope — without it, `.flex()`, `.bg()` and `.on_click()` do not resolve.

The style helpers are Tailwind-shaped and generated by macros, so they are not
in `styled.rs`. They follow these rules:

- spacing: `p_1 … p_8`, `px_2`, `py_3`, `pt_1`, `mt_4`, `mb_2`, `mx_3`, `gap_1 … gap_8`
- size: `w_full`, `h_full`, `size_full`, `w(px(208.0))`, `h(px(34.0))`, `w(px(120.0))`
- shape: `rounded_md`, `rounded_full`, `border_1`, `border_b_1`, `border_r_1`, `border_color(c)`
- color: `bg(c)`, `text_color(c)`, `opacity(0.5)`
- text: `text_xs`, `text_sm`, `text_base`, `text_lg`, `text_xl`, `font_weight(gpui::FontWeight::Semibold)`, `truncate`, `whitespace_normal`, `text_align(gpui::TextAlign::Right)`
- layout: `flex`, `flex_col`, `flex_row`, `flex_1`, `flex_none`, `items_center`, `justify_between`, `absolute`, `relative`, `overflow_y_scroll`, `cursor_pointer`
- grid: `grid`, `grid_cols(3)`, `col_span(2)`, `row_span(2)`

If a helper does not resolve, the compiler says so — do not guess a name, look
it up:

```sh
grep -o 'fn [a-z_0-9]*' ~/.cargo/registry/src/index.crates.io-*/gpui-macros-0.2.2/src/styles.rs | sort -u
```

Colors are `gpui::rgb(0xrrggbb)`, `gpui::rgba(0xrrggbbaa)`, `gpui::hsla(h, s, l, a)`.
`Rgba` converts into `Hsla` with `.into()`.

## Text

`div().child("plain string")` renders text. For mixed styling use
`gpui::StyledText` with `gpui::TextRun` runs (see `src/elements/text.rs`).

## Entities

```rust
let entity = cx.new(|cx| MyView::new(cx));       // Entity<MyView>
entity.update(cx, |view, cx| { view.count += 1; cx.notify(); });
let value = entity.read(cx).count;
div().child(entity.clone())                        // Entity<V: Render> is an element
```

`cx.notify()` marks the view dirty — without it a state change never repaints.

## Globals

```rust
cx.set_global(Session::new(base));                       // once, at startup
cx.read_global::<Session, _>(|session, _| session.client())  // read
cx.update_global::<Session, _>(|session, _| session.sign_out()) // write
```

## Async

`Context::spawn` gives `(WeakEntity<Self>, &mut AsyncApp)`:

```rust
cx.spawn(async move |this, cx| {
    let result = do_something().await;
    let _ = this.update(cx, |view, cx| { view.data = result; cx.notify(); });
})
.detach();
```

`AsyncApp` implements `AppContext`, so `entity.update(cx, …)` works with it.
`cx.spawn` must be `detach()`ed or the task is dropped.

Blocking work (the HTTP calls) belongs on a worker thread — see
`api::spawn_request`, which does exactly that.

## Events

```rust
div()
    .on_click(cx.listener(|this, event, window, cx| { … }))
    .on_key_down(cx.listener(|this, event, window, cx| { … }))
    .track_focus(&self.focus)
    .tab_stop(true)
```

`cx.listener` turns a `Fn(&mut T, &E, &mut Window, &mut Context<T>)` into the
`Fn(&E, &mut Window, &mut App)` shape the element wants.

Key names (`Keystroke::key`): `backspace`, `delete`, `left`, `right`, `up`,
`down`, `home`, `end`, `enter`, `escape`, `tab`, `space`. Printable characters
arrive in `keystroke.key_char`.

## Focus, clipboard, IME

```rust
let focus: FocusHandle = cx.focus_handle();   // Context/Window::focus_handle()
window.focus(&focus);
focus.is_focused(window);
cx.read_from_clipboard().and_then(|item| item.text());  // Option<String>
cx.write_to_clipboard(gpui::ClipboardItem::new_string(text));
```

For real text input — IME, marked text, clipboard selection — gpui expects
the view to implement `gpui::EntityInputHandler` and to register
`gpui::ElementInputHandler::new(bounds, entity)` with
`window.handle_input(&focus, handler, cx)` during paint. The trait is in
`src/input.rs`; its methods are `text_for_range`, `selected_text_range`,
`marked_text_range`, `unmark_text`, `replace_text_in_range`,
`replace_and_mark_text_in_range`, `bounds_for_range`,
`character_index_for_point`.

`widgets/input.rs` implements `EntityInputHandler` (see "Text input, for real"
below): the caret, the selection and the marked text are painted by the
widget itself. Typing still comes from key events, not from `insertText:` —
there is a reason for that, and the section explains it.

## Long lists

`gpui::uniform_list(id, item_count, |range, window, cx| vec![…])` renders only
the visible rows. `gpui::list` is the non-virtualized variant. Use
`uniform_list` for the log views — the call log can be thousands of rows.

## Measuring text

`window.text_system()` exposes the text system; `TextSystem::shape_line` and
friends give glyph advances, which is how a caret or a selection highlight is
positioned. `src/text_system.rs` has the details.

The concrete call, as the text input widget uses it:

```rust
let shaped = window.text_system().shape_line(
    text.into(),            // SharedString
    px(13.0),               // font size
    &[TextRun { text: text.into(), ..Default::default() }],
    None,                   // no stylesheet
);
```

Three things about it are not obvious:

* **An empty `TextRun` list measures zero.** The run has to cover the text,
  otherwise the shaped line has no advance at all and every offset lands at
  x = 0.
* **The line must not contain `'\n'`** — `shape_line` debug-asserts on it.
* **The offsets are UTF-8 *byte* offsets**, not character indices:
  `LineLayout::x_for_index(byte)` and `closest_index_for_x(x)` work on bytes.

`ShapedLine`'s own fields are `pub(crate)`, but it derefs to `LineLayout`, so
`x_for_index`, `closest_index_for_x`, `ascent`, `descent` and `width` are
reachable through the deref.

## Text input, for real

The dashboard's only text field is `desktop/gpui/src/widgets/input.rs`. It is
worth writing down what a custom gpui text field actually needs, because every
item below cost a compile error or a wrong pixel.

* **`window.handle_input(...)` may only be called during the *paint* phase.**
  It asserts the phase, so it cannot be called from `Render::render` — the
  widget needs a small custom `Element` whose `paint` does the registration.
  `AnyElement`'s inherent `request_layout` / `prepaint` / `paint` take
  `(window, cx)` and shadow the trait methods, so a custom element has to call
  them explicitly.
* **The handler's ranges are UTF-16 units**, not bytes and not characters.
  `text_for_range`, `selected_text_range` and `marked_text_range` speak
  UTF-16; the widget keeps byte offsets internally and converts.
* **`bounds_for_range` returns *window-local* coordinates.** On macOS the
  platform adds the window frame origin itself, so passing screen coordinates
  double-counts the frame.
* **`TextRun.background_color` paints behind the glyphs** — that is how the
  selection is drawn. `StyledText::with_runs` asserts that the runs cover the
  text exactly, in bytes.
* **A click positions the caret from the bounds captured at the last
  prepaint**, so `character_index_for_point` works at most one frame late.
* **On macOS the platform only calls `insertText:` for keys the widget does
  *not* consume.** A widget that calls `cx.stop_propagation()` in its key
  handler therefore never sees `insertText:` — routing typing through the IME
  path would make every keystroke depend on a platform callback. That is why
  the widget types from key events and only uses the input handler for
  marked text, the clipboard and the candidate window.

Not implemented, and deliberately so: a blinking caret (it needs a timer),
drag-selection and double-click word selection.

## What gpui does **not** have

No `Button`, no `Input`, no `Table`, no `Select`, no `Tabs`, no `Toast`, no
date picker, no chart widget, no theme system. `desktop/gpui/src/widgets/`
holds the ones this dashboard needs — and only those.

## API surprises found while porting

The facts below each cost time during the Tauri → GPUI port. They are not
obvious from the docs, and some of them contradict what the API looks like
from the outside. Line numbers refer to the crate source on this machine:

```sh
GP=$(ls -d ~/.cargo/registry/src/index.crates.io-*/gpui-0.2.2 | head -1)
```

### `Application` is a struct, not a trait

```rust
Application::new().run(move |cx: &mut App| { … });
```

It looks like a trait you are supposed to implement — it is not. `App` is the
trait; `Application` is the entry point. `desktop/gpui/src/main.rs` uses it
directly.

### The style helpers are macros, and the compiler is the authority

`p_4`, `bg`, `rounded_md`, `flex_col`, `gap_2`, `text_sm` … are Tailwind-shaped,
but they are **not** functions in `styled.rs` — they are generated by the
macros in `gpui-macros` (`src/styles.rs` there). Looking for them in
`gpui/src/styled.rs` finds nothing, and the docs do not list them.

So: when a helper does not resolve, do not guess a near-synonym
(`font_weight(gpui::FontWeight::Semibold)` does not exist — see below). Look
the name up:

```sh
grep -o 'fn [a-z_0-9]*' ~/.cargo/registry/src/index.crates.io-*/gpui-macros-0.2.2/src/styles.rs | sort -u
```

The compiler error names the missing method; the macro source names the
helper. Between the two, nothing has to be guessed.

### The interactive methods need an id first

`.id(...)` does not add a method — it changes the **type**: `InteractiveElement::id`
returns `Stateful<Self>` (`gpui/src/elements/div.rs:607`), a wrapper that
implements `StatefulInteractiveElement` (`div.rs:2916`).

So `on_click`, `on_hover`, `on_drag`, `overflow_y_scroll`, `overflow_scroll`,
`focusable`, `tooltip` and `hoverable_tooltip` are methods of
`StatefulInteractiveElement` — they only resolve **after** `.id(...)`:

```rust
div()
    .id(theme::unique_id("content"))
    .overflow_y_scroll()
    .on_click(cx.listener(|this, event, window, cx| { … }))
```

`on_key_down`, `capture_key_down`, `track_focus` and `tab_stop` are plain
`InteractiveElement` methods (`div.rs:596`) and resolve on a plain `div()` as
well — but they need a focus handle to fire, so the port puts `.id()` first
anyway (`src/widgets/input.rs`).

And **every id must be unique**. The element state is kept in a map keyed by
`(GlobalElementId, TypeId)` (`gpui/src/window.rs:670`), so two elements that
share an id share one state: a scroll offset written by one is read by the
other, and focus handling follows the wrong element. The crate therefore never
writes an id by hand — `theme::unique_id(prefix)` draws from an atomic counter
and wraps `ElementId::named_usize`.

### `use gpui::prelude::*;` is mandatory

It brings `Styled`, `InteractiveElement`, `IntoElement` and `AppContext` into
scope. Without it, `.flex()`, `.bg()` and `.on_click()` do not resolve and the
error mentions an unknown method rather than a missing import — which is the
easy way to lose an hour.

### `cx.borrow_mut()` is ambiguous

`Context` implements `BorrowMut<App>`, but `&mut Context` also implements
`BorrowMut<Context>`, so the plain call does not know which impl is meant.
Name it:

```rust
pub fn app_mut<'a, T>(cx: &'a mut gpui::Context<'_, T>) -> &'a mut gpui::App {
    <gpui::Context<'_, T> as std::borrow::BorrowMut<gpui::App>>::borrow_mut(cx)
}
```

That helper lives in `desktop/gpui/src/api.rs` (`api::app_mut`) and every view
uses it instead of `cx.borrow_mut()`.

### `read_entity` returns the value, not a `Result`

`Context::read_entity` has the signature `fn read_entity<U, R>(&self, handle,
read) -> Self::Result<R>`, and `Context::Result<U>` is **the value itself**
(`gpui/src/app/context.rs:737`: `type Result<U> = U;`). It is not an
`std::result::Result` — so there is nothing to `unwrap`, and writing `.unwrap()`
on it is a compile error that looks like a typo.

```rust
let value = cx.read_entity(&self.key_input, |input, _app| input.value().to_string());
```

`AsyncApp::read_entity` is the opposite: it returns a real `Result` and needs
`.context("…")`.

### `FontWeight::SEMIBOLD`, not `FontWeight::Semibold`

The constants are upper case (`gpui/src/text_system.rs:670`):

```rust
FontWeight::NORMAL     // 400
FontWeight::SEMIBOLD   // 600
```

`FontWeight` *does* implement `Default`; `Font` does **not** (there is no
`impl Default for Font` in the crate).

### `CursorStyle::PointingHand`, `CursorStyle::IBeam`

The variants are named after the macOS cursors, in the same PascalCase as the
enum: `CursorStyle::PointingHand`, `CursorStyle::IBeam`,
`CursorStyle::Arrow`. `CursorStyle::PointingHand` is what a clickable row
wants.

### `Modifiers::platform`, not `Modifiers::command`

`Modifiers` has a `platform` field (`gpui/src/platform/keystroke.rs:465`),
which is ⌘ on macOS. There is no `command` field — on Linux and Windows the
same field is Ctrl.

### The clipboard

```rust
gpui::ClipboardItem::new_string(text.to_string())   // takes an owned String
item.text()                                         // Option<String>
```

`new_string` takes a `String`, not a `&str`. `text()` returns `None` when the
item holds no string entry (an image, for example) — so `and_then(|item|
item.text())` is the idiomatic read.

### Element ids must be *stable*, not unique

```rust
ElementId::named_usize("content", 0)   // gpui/src/window.rs:4887
```

gpui keeps the interaction state of an element (`pending_mouse_down`,
`clicked_state`) **by element id** (`gpui/src/elements/div.rs:2122`,
`:2134`, `:2212`; `gpui/src/window.rs:3677` dispatches the mouse event).
An id that changes between the mouse-down and the mouse-up therefore
**loses the click**: the handler never fires.

So the counter has to be *stable per element*, not per render. A global
atomic counter — `theme::unique_id()` — hands out a fresh id on every frame
and silently breaks every `on_click` in the app. The crate uses
`theme::element_id(name)` instead: the caller passes a name that identifies
the element (a row id, a button key), and the same element gets the same id
on every render.

Two ids must also not collide: during the capture phase the mouse-up of one
element resets the `pending_mouse_down` of another that happens to share its
id, and that click is lost as well.

### `gpui::relative()` is a fraction, not a percentage

```rust
gpui::relative(0.25)   // gpui/src/geometry.rs:3567
```

`relative(fraction)` takes a **fraction between 0.0 and 1.0** of the parent
size — `1.0` is 100% (`DefiniteLength::Fraction`). Passing `25.0` does not
mean 25%; it means 25 times the parent width, and the child overflows the
window. A bar chart built as `relative(fraction * 100.0)` renders every bar
hundred times too long.

### Long lists

`gpui::uniform_list(id, count, |range, window, cx| vec![…])`
(`gpui/src/elements/uniform_list.rs:22`) renders only the visible rows. The
call log can be thousands of rows, so the log view virtualises; `gpui::list`
is the non-virtualised variant.

### Key names

`Keystroke::key` is a `&str` with these names (`gpui/src/platform/keystroke.rs`):

```
backspace  delete  left  right  up  down  home  end  enter  escape  tab  space
```

Printable characters do **not** arrive in `key` — they arrive in
`keystroke.key_char`. A handler that compares `key` against a literal
character never fires.

### `gpui::font(family)`

`gpui::font("SF Mono")` builds a `Font` (`gpui/src/text_system.rs:807`). `Font`
has no `Default`, so a font has to be named explicitly; the style helpers
carry the family as a string, and the crate's monospace family is
`theme::MONO_FAMILY` with `theme::MONO_FALLBACK` behind it.
