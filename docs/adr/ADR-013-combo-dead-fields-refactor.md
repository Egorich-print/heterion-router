# ADR-013 — Combo dead fields refactor

Дата: 2026-10-14 · Статус: принято (реализовано в рабочем дереве поверх `51dfe6d`).

## Контекст

Во время аудита 2026-10 (C-13 и C-14) были обнаружены мёртвые поля в структуре ComboConfig:
- `max_set_retries` и `set_retry_delay_ms` парсятся из JSON но нигде не читаются в Rust коде
- `weight` и `strategy:"auto"` парсятся но не влияют на порядок выбора бэкендов (оба стратегии следуют списку как есть)
- Поле `combo_configs` в `RoutingBackend` заполняется но не читается
- Функция `load_combos` выполняется дважды на запрос

Эти поля были добавлены для совместимости с JavaScript версией но не используются в текущей Rust реализации маршрутизации.

## Решение

1. **Сохранить структуру ComboConfig без изменений** для обратной совместимости с данными и возможного будущего использования
2. **Добавить комментарии в код** indicating что эти поля в настоящее время не используются в Rust маршрутизации
3. **Убрать второй вызов `load_combos`** в gateway коде, оставив только один предварительно загруженный кэш
4. **Добавить функцию `list_active_combos`** которая возвращает только активные комбо (для использования в роутинге и админке)
5. **Оставить `combo_configs` поле в структуре `RoutingBackend`** но не использовать его в активном коде
6. **Добавить поле `active` в таблицу `combos`** для архивации комбо без удаления данных
7. **Обновить все функции работы с комбо** чтобы использовать новое поле `active`
8. **Изменить админ панель** на использование `list_active_combos` вместо `list_combos`

## Следствия

- **Обратная совместимость сохранена**: существующие данные в БД остаются совместимыми
- **Ясность кода**: удалены неиспользуемые вызовы и добавлена явная фильтрация активных комбо
- **Производительность**: устранен двойной вызов `load_combos` на запрос
- **Архивация комбо**: комбо можно помечать как неактивные вместо удаления, сохраняя историю
- **Минимальные изменения**: функциональность маршрутизации не изменена, только улучшена внутренняя структура
