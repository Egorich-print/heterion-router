# ADR-016 — exa-search integration as search tool

Дата: 2026-10-14 · Статус: принято (реализовано в рабочем дереве поверх `51dfe6d`).

## Контекст

Пользователь указал что exa-search должен быть проверен как поисковый инструмент, а не автоматически рассматриваться как обычная чат-модель.
Аудит показал что exa-search отсутствует в реестре провайдеров (registry.json) и не интегрирован в систему.
Текущая система имеет механизмы для обработки инструментов (инструменты вызова функций) но нет специальной интеграции для поисковых провайдеров.

Exa-search это специализированный поисковый API который возвращает структурированные результаты веб-поиска с цитированием источников, что отличается от обычных чат-моделей генерации текста.

## Решение

1. **Добавить exa-search в registry.json** как провайдера с:
   - `id`: "exa-search"
   - `alias`: "exa"
   - `format`: "custom" (специфичный формат для поисковых API)
   - `executor`: "exa" (специфичный исполнитель для обработки поисковых запросов)
   - `auth_type`: "apikey" (использует API ключ аутентификацию)
   - `base_url`: "https://api.exa.ai/v1" (официальный endpoint exa-search)
   - `models`: [{"id": "exa-search", "target_format": "search"}] (специфичный target format для различения от чат-моделей)

2. **Сохранить exa-search как поисковый инструмент**:
   - Не интегрировать exa-search в обычный поток чат-моделей
   - Оставить его доступным только как специализированный поисковый инструмент
   - Интегрировать с существующим механизмом инструментов если он существует, либо оставить для будущей интеграции через инструменты вызова функций

3. **Добавить необходимые тесты** для проверки интеграции:
   - Тест на правильное добавление в реестр
   - Тест на доступность провайдера через реестр
   - План на будущую интеграцию с инструментами вызова функций когда потребуется

## Следствия

- **Ярко выраженное разделение обязанностей**: exa-search используется только для поисковых запросов, не для генерации чат ответов
- **Готовность к будущей интеграции**: структура реестра подготовлена для добавления специализированных провайдеров
- **Минимальные риски**: добавление нового провайдера не влияет на существующую функциональность чат-моделей
- **Соответствие требованиям пользователя**: exa-search проверен как поисковый инструмент, не как чат-модель
- **Расширяемость**: легче добавлять другие специализированные провайдеры в будущем
