# ADR-021 — agentrouter: Responses-протокол и идентификация клиента

Дата: 2026-10-27 · Статус: принято (реализовано в рабочем дереве поверх `563bf00`).

## Контекст

Провайдер `agentrouter` был заведён в реестре как `format: "claude"`,
`base_url: https://agentrouter.org/v1/messages`, с моделями
`claude-opus-4-8`, `claude-opus-5` и `gpt-5.6-sol`. Живые вызовы к нему
давали `401`, в `call_logs` — две записи 401 (13:35 2026-10-26 и 2026-10-14),
хотя в сентябре тесты соединения проходили.

Живая проверка 2026-10-27 показала, что дело не в ключе, а в трёх вещах:

1. **Клиент-детект.** Площадка меряет квоту по типу клиента и отвечает
   `401 unauthorized_client_error` («unauthorized client detected») на запрос
   без распознанного клиента — даже с валидным ключом. Проверено: без
   отпечатка — 401, с browser user-agent — 401, с `originator: codex_cli_rs` —
   200. Заголовка `originator` достаточно; user-agent на детект не влияет.
2. **Протокол.** Все живые модели площадки отвечают только на
   `POST /v1/responses`; `/v1/chat/completions` отвергается
   (`400 不支持 /v1/chat/completions 接口，请改用 /v1/responses`).
3. **Каталог моделей.** `GET /v1/models` (с ключом) отдаёт ровно три модели:
   `gpt-6.1-sol`, `gpt-6-astra`, `gpt-5.6-sol`. Claude-модели нашей группе
   недоступны: в `GET /api/pricing` у `claude-opus-5-5` перечислены группы
   `svip`/`test`, а у нас группа `default` (`group_ratio: {"default": 1}`).
   Отсюда и прежний `503 当前分组 default 下对于模型 … 无可用渠道` —
   модель `claude-opus-4-8` в каталоге площадки отсутствует.

Дополнительно: площадка публикует правила (лимиты, батчи в 10:00/19:00
UTC+8, `402 Budget pool quota has been exhausted`, перечень поддерживаемых
клиентов, где `codex` — поддерживаемый; неподдерживаемый клиент попадает в
группу `probation` с двойным множителем).

## Решение

**Формат и адрес.** `agentrouter` переводится на
`format: "openai-responses"`, `base_url: https://agentrouter.org/v1/responses`.
Модели в реестре — только те, что отдаёт `GET /v1/models`: `gpt-6.1-sol`,
`gpt-6-astra`, `gpt-5.6-sol`. Устаревшие идентификаторы (`claude-opus-4-8`,
`claude-opus-5`) удалены: они в каталоге площадки отсутствуют, и их
наличие в реестре обещает клиенту модели, которой нет.

**Идентификация клиента** — новый модуль `client_profile.rs`:
политика «какие дополнительные заголовки шлёт провайдеру», по образцу
`reasoning.rs`. Для `agentrouter` отправляется

- `originator: codex_cli_rs` — обязательный для авторизации заголовок;
  площадка читает именно его, и `codex` входит в перечень поддерживаемых
  клиентов (протокол `/v1/responses` и есть протокол Codex);
- `user-agent: heterion-router/<version> (codex-responses client)` —
  собственный user-agent роутера, а не заимствованная версия Codex CLI:
  группа (и с ней множитель) от user-agent не зависит — все варианты,
  проверенные 2026-10-27, сообщили одну и ту же группу `default`.

Отпечаток — свойство провайдера, а не глобальное правило: `headers_for()`
возвращает пусто для всех остальных (тест
`other_providers_keep_their_own_headers`).

**Ключ.** Менять не нужно: в `provider_connections.api_key` уже лежит
зашифрованное (`enc:v1:`) значение того же ключа — 51 символ в открытом виде,
что совпадает с ключом, предъявленным оператором 2026-10-27. Значение в БД
не менялось и нигде не дублировалось.

**Embeddings.** Поведение не изменилось: у провайдера нет
`/v1/embeddings`, запрос отвергается 404 до похода вверх. Тест больше не
привязан к формату провайдера (формат менялся — тест падал).

**Побочный дефект: `error: null`.** Живая проверка вскрыла ошибку роутера,
не площадки: объект Responses API **всегда** содержит поле `error`, и в
успешном ответе оно равно `null`. Пул кредитов (`try_each_credential`)
считал любое наличие ключа `error` отказом и подставлял `upstream_refusal`
от `null` → `502 upstream error: null` вместо текста модели. Отказом
считается только непустой объект ошибки. Дефект был общим для всех
Responses-провайдеров (`deepseek`, `codex`, `perplexity-agent`), не только
для agentrouter.

## Следствия

- `agentrouter` обслуживается `ResponsesBackend`-ом: маршрутизация, перевод
  chat→responses, стриминг (`response.created` / `response.output_text.delta`
  / `response.completed`) — уже поддержаны и проверены живыми вызовами.
- Claude-wire бэкенд (ADR-018/ADR-020) остаётся для `zai`, `kimi-coding`
  и прочих claude-провайдеров; `agentrouter` из него уходит.
- ADR-017 («agentrouter — `claude`-формат») теряет актуальность в части
  формата; его вывод про embeddings и про отсутствие петель остаётся в силе.
- Площадка отвечает нестабильно по времени (зависания до 180 с, успехи от
  6 с). Квота выдаётся батчами, поэтому живой ответ может прийти с `402`
  или `503` — это свойство площадки, а не дефект роутера.
- Если площадка сменит протокол или набор моделей, правятся реестр и
  `client_profile.rs`; оба места теперь в одном файле проверки.

- `crates/heterion-router-gateway/tests/agentrouter.rs` — красный до фикса
  (формат реестра, отсутствие отпечатка в запросе), зелёный после.
- `responses::tests::a_successful_payload_whose_error_field_is_null_is_not_an_error`
  — красный до фикса (`Upstream("null")`), зелёный после.
- `scripts/ci/check.sh` → `check.sh: all green`.
- Живые вызовы 2026-10-27 через сам роутер: `agentrouter/gpt-6.1-sol` —
  200 `finish_reason: stop` (текст `OK`) и 200 в стриме (3 чанка, `data:
  [DONE]`); `agentrouter/gpt-5.6-sol` — 200; `agentrouter/gpt-6-astra` —
  502 `server_error` от канала площадки. Прямые вызовы: все три модели —
  200 `status: completed`, стрим — `event: response.created` …
  `response.completed`.
