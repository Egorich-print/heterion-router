# ADR-002. Дашборд раздаёт сам шлюз

> Дата: 2026-09-18 · Статус: accepted

## Контекст

У JS-версии дашборд был отдельным Next.js-сервером на том же порту, что и API
(`:20128`). У Rust-порта интерфейса не было вовсе: `/` отвечал 404, состояние
провайдеров и комбо приходилось выяснять вручную.

Альтернативы: отдельный Node/статика-сервер; Tauri только как способ смотреть
UI; SPA, раздаваемый axum.

## Решение

SPA (Svelte 5 + Vite) собирается в `desktop/ui/dist` и раздаётся **самим
шлюзом** на том же origin, что и API. Это тот же адрес, что был у JS-дашборда,
поэтому клиенты (закладки, `localhost:20128`) не меняются, а авторизация
работает тем же bearer-ключом без CORS.

`tower-http` для статики не добавлен: хендлер `ui::serve` умеет SPA-fallback,
защиту от обхода каталога и внятное сообщение «UI не собран». Каталог
переопределяется `OMNIROUTE_UI_DIR`.

## Следствия

- Один процесс — один порт — один origin. Нет второго сервиса и второго способа
  авторизации.
- Бандл обязан быть собран до старта шлюза; при отсутствии — API работает, `/`
  объясняет, что делать.
- Tauri-оболочка переиспользует тот же бандл (см. ADR-007), а не второй UI.
