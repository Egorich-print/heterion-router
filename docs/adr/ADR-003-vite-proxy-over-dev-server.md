# ADR-003. Dev-режим UI: Vite-proxy, без второго бэкенда

> Дата: 2026-09-18 · Статус: accepted

## Контекст

Для быстрой работы над UI хочется hot-reload Vite (`:5173`), но API живёт на
`:20128`. Можно было бы поднять в dev отдельный шлюз, управлять его жизненным
циклом из npm-скриптов или проксировать запросы.

## Решение

`vite.config.js` проксирует `/api`, `/v1` и `/healthz` на `http://127.0.0.1:20128`
(`VITE_GATEWAY_URL` переопределяет). Dev-сервер остаётся чистым фронтендом —
никакого процесса-обёртки и никакой второй реализации API.

## Следствия

- `npm run dev` требует уже запущенного шлюза; отсутствие шлюза даёт честную
  ошибку сети, а не скрытый фолбэк.
- В продакшене прокси не участвует: тот же код работает с того же origin.
- Прод-сборка не зависит от dev-настроек — `apiBase()` различает окружения.
