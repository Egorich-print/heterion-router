# ADR-011 — Границы миссии MISSION-2026-10 и «схема ≠ enforcement»

- Статус: **принят** (2026-09-29)
- Связан с: `docs/MISSION-2026-10.md`, `docs/ROADMAP-2026-09.md`,
  `docs/research/PROJECT-AUDIT-2026-09.md`, ADR-009, ADR-010

## Контекст

Аудит 2026-09-29 и шесть параллельных архитектурных отчётов зафиксировали 24
подтверждённых дефекта корректности, 10 операционных находок и 12 coverage-gap'ов.
Наивная реакция — расширить milestone до «исправить всё, что нашли». Это
воспроизводит уже наблюдаемую проблему проекта: за последние месяцы граница
между «схема поддерживает» и «шлюз это делает» размылась (`maxSetRetries`,
`setRetryDelayMs`, `weight`, `strategy:"auto"`, quota-колонки `api_keys`,
`usage_limit_enabled`, `max_sessions`), и UI продолжает предлагать то, что
маршрутизатор игнорирует.

Одновременно миссия упирается в решения, которые меняют продуктовый контракт и
не могут быть приняты агентом: fail-closed policy для legacy-ключей, шифрование
Responses-store at-rest, нужен ли store продукту вообще (0 production-строк),
псевдонимизация third-party идентификаторов в evidence.

## Решение

1. **Миссия ограничена дефектами, а не фичами.** MISSION-2026-10 закрывает
   четыре измеримых результата: O-1 (нет silent loss на Responses), O-2 (нет
   утечки upstream в SSE), O-3 (достоверная атрибуция), O-4 (воспроизводимый
   baseline). Всё, что не ведёт к этим результатам, — вне миссии.

2. **Non-goals закреплены явно** (§3 `docs/MISSION-2026-10.md`): native Anthropic
   Messages backend, ChatHub как upstream, WebSocket/MCP/Conversations/background
   jobs, полный Grok conformance harness, notarization, TLS-терминация, quota
   enforcement, реализация `weight`/`strategy:"auto"`, несовместимое изменение
   `enc:v1:`/`STATIC_SALT`.

3. **Принцип «схема ≠ enforcement».** Наличие колонки или поля в JSON-конфиге не
   считается реализованной функцией. Для каждого неиспользуемого поля миссия
   выбирает одно из двух: реализовать с тестом (H1) или удалить из UI и
   документировать (H2/H3). Третьего варианта — «оставить и hope» — нет.

4. **Сначала красный тест, потом фикс.** Ни один дефект C-1…C-24 не закрывается
   без падающего теста, который был красным до фикса. Обоснование: 22 вызова
   `wiremock.expect()` и 0 вызовов `verify()` в текущем дереве.

5. **Живой сервис не является средством верификации.** Mission-правки проверяются
   только на чистом clone + `scripts/ci/check.sh` + wiremock. Launchd-инстанс на
   `0.0.0.0:20128` запущен из dev-дерева и не отражает mission-код.

6. **Решения владельца не принимаются агентом.** Девять пунктов §13
   `docs/MISSION-2026-10.md` (fail-closed vs parity, класс развёртывания,
   шифрование store, нужность store, commit-only PR, UI-тест-раннер, property
   testing, desktop-тесты в CI, third-party идентификаторы) блокируют
   соответствующие задачи до явного ответа. Действие по умолчанию для каждого
   зафиксировано, чтобы миссия могла стартовать без простоя.

7. **Ответы владельца фиксируются здесь, а не в коде.** Каждое решение по Q1–Q9
   получает addendum к настоящему ADR с датой и обоснованием; молчаливая правка
   теста вместо записи решения запрещена.

## Следствия

**Положительные**
- Milestone остаётся исполнимым: ядро (WS-A + WS-B + WS-D) — 9–14.5 человеко-дня.
- Регрессии test-locked контракта (E1, E4) требуют ADR-записи, а не тихой правки.
- Репозиторий достигает состояния, где `git clone` + один скрипт дают полный ответ
  «можно ли это релизить».

**Отрицательные**
- Часть находок аудита сознательно остаётся незакрытой: quota enforcement,
  Anthropic backend, TLS, notarization. Это явный долг, а не забытый пункт.
- Milestone добавляет ~77 тестов; при 213 текущих это рост порядка 36%, что
  замедлит гейт — приемлемо, порог в 60 s зафиксирован в отчёте `06`.
- Владелец обязан ответить на 9 вопросов; без ответов применяются действия по
  умолчанию, часть которых (Q3, Q4) сознательно оставляет дисковое хранилище
  Responses без шифрования.

**Совместимость**
- ADR-001..010 не переписываются; настоящий ADR их дополняет.
- Frozen-контракты (env precedence, data-dir, порты, `enc:v1:`, hash-only
  issuance shape, launchd label) не меняются.

## Что этот ADR не решает

evidence — в `docs/research/PROJECT-AUDIT-2026-09.md` и
