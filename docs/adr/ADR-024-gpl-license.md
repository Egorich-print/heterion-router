# ADR-024 — лицензия GPL-3.0-or-later для всего дерева

Дата: 2026-11-11 · Статус: принято (реализуется в рабочем дереве).

## Контекст

Проект — Rust-порт OpenAI-совместимого шлюза, портированный с JS-upstream
`diegosouzapw/OmniRoute`. Upstream распространялся под MIT, и это зафиксировано
в истории проекта: ADR-008 §4 («Лицензия MIT, с сохранением
`Copyright (c) 2026 diegosouzapw` + `Copyright (c) 2026 Egorich-print`»).
ADR-008 — историческое решение, и оно остаётся в репозитории как факт: на
момент переименования лицензия действительно была MIT.

Готовится первый публичный релиз. Возникает вопрос лицензии для дерева, в
котором смешаны собственная работа (Rust-шлюз, GPUI-оболочка, Svelte-дашборд)
и производные части от MIT-upstream.

Факты, которые определяют выбор:

| Факт | Значение |
|---|---|
| Лицензия до этого решения | MIT (ADR-008 §4), копирайты сохранены |
| Зависимости Rust | crates.io — преимущественно MIT / Apache-2.0 / BSD (`THIRD_PARTY_NOTICES.md`) |
| Зависимости GPUI-оболочки | `gpui` (Apache-2.0), `reqwest`, `serde` — MIT/Apache-2.0 |
| JS-часть | `desktop/ui` (Svelte) и `desktop/gpui/tools/mcp/server.js` — собственная работа этого репозитория |
| Upstream-материал в репозитории | `docs/history/` — три **отчёта** (`task-c1/c2/c3-report.md`) о замороженной JS-работе, а не исходный код upstream (ADR-008, фактическое уточнение 2026-09-29) |
| Upstream-исходники | не вендорены: отдельный репозиторий-архив, пути `src/app/**` в этом дереве отсутствуют |
| Формат публикации | готовый `.app` (ad-hoc подпись, без нотаризации) + исходники в публичном репозитории |

GPLv3 — лицензия, совместимая с MIT, Apache-2.0 и BSD по лицензионному
требованию: она требует от распространятеля предоставления исходников и права
их изменения, но не запрещает коммерческое использование.

## Решение

**Всё дерево лицензируется как GPL-3.0-or-later.** «or-later» — потому, что
код можно распространять и на более поздних версиях GPL; это даёт получателям
кода свободу выбора, не снимая с автора обязанности предоставить исходники.

**Канонический текст лицензии — в `LICENSE`.** Файл содержит полный текст
GNU GPL версии 3, перед ним — шапка с копирайтами:

```
Heterion Router
Copyright (C) 2026 Egorich-print and the Heterion Router contributors

Portions of this project were derived from the OmniRoute upstream work
Copyright (c) 2026 diegosouzapw
```

Копирайт upstream-автора сохраняется — GPL требует сохранять уведомления о
правах при распространении производных работ.

**Метаданные лицензии — в манифестах:**

- `Cargo.toml` (workspace): в `[workspace.package]` — `license = "GPL-3.0-or-later"`;
  каждый крейт наследует его через `license.workspace = true`
  (`crates/heterion-router-*/Cargo.toml`);
- `desktop/gpui/Cargo.toml` — то же поле отдельной строкой: крейт GPUI-оболочки
  вне workspace (ADR-023) и наследовать не может;
- `desktop/gpui/tools/mcp/package.json` — поле `"license": "GPL-3.0-or-later"`.

**ADR-008 не переписывается.** §4 остаётся в истории как зафиксированный факт
о лицензии на момент переименования; решение по лицензии изменяется здесь.
Ранее принятые ADR не переписываются — это правило проекта (ADR-008,
«Последствия»: «старые ADR-001..007 и `docs/history/` не переписываются
(фиксация фактов)»).

**Границы применимости.** GPL распространяется на всё дерево репозитория:
workspace-крейты, GPUI-оболочку, Svelte-дашборд, MCP-сервер, скрипты и
документацию.

## Следствия

**Хорошо.** Пользователь может форкать проект, изменять его и распространять
изменённую версию — при распространении он обязан предоставить полный
исходный код под GPL-3.0-or-later и сохранить уведомления о правах. То есть
приложение можно дорабатывать под себя и делиться результатом; закрытый форк
при распространении невозможен, но и не требуется.

Зависимости не мешают: MIT, Apache-2.0 и BSD совместимы с GPLv3, поэтому
связка «GPL-3.0-or-later + MIT/Apache-2.0/BSD-зависимости» легальна, и
`THIRD_PARTY_NOTICES.md` остаётся точкой, где перечисляются сторонние
лицензии.

`docs/history/` конфликта лицензий не создаёт: там лежат **отчёты** о
замороженной JS-работе upstream, а не его исходный код. Upstream-исходники в
репозиторий не вендорились (ADR-008 §5), поэтому смешивания MIT- и
GPL-лицензий в одном файле не возникает. Копирайт `diegosouzapw` сохранён в
шапке `LICENSE` и в `THIRD_PARTY_NOTICES.md`.

**Плохо / ограничения.**

- Лицензия меняется **в одну сторону**: код, полученный под MIT, больше нельзя
  распространять как MIT — только как GPL-3.0-or-later. Для тех, кто уже
  использовал MIT-версию, это изменение условий.
- GPLv3 — копилефт: любой, кто распространяет бинарный бандл (`Heterion
  Router.app`), обязан приложить текст лицензии и предоставить исходники.
  На практике это означает, что вместе с `.app` публикуются исходники
  (публичный репозиторий) и `LICENSE`.
- Код под GPLv3 нельзя включать в закрытые продукты без соответствия GPL —
  это ограничение для вендоров, а не для пользователей.

**Следствия для процесса.** Ни один новый файл в дереве не может прийти под
другой лицензией, если он распространяется вместе с проектом; для собственных
зависимостей лицензии перечисляются в `THIRD_PARTY_NOTICES.md`. Поле
`license` в манифестах — единственное машинно-читаемое объявление лицензии,
поэтому при добавлении нового крейта вне workspace значение нужно продублировать
явно, как это сделано для `desktop/gpui`.

**Язык интерфейса и документации.** Интерфейс обоих фронтендов — английский:
нативная GPUI-оболочка (`desktop/gpui`) и веб-дашборд на Svelte
(`desktop/ui`). Документация проекта — русская: ADR, `README.md`,
`STATUS.md`, `docs/INSTALL.md`, `docs/PROVIDERS.md`. Это осознанное решение, а
не недосмотр: английский интерфейс адресован техническому пользователю
(разработчику, который ставит шлюз и настраивает провайдеров) и совпадает с
языком API и с терминологией провайдеров, а документация читается владельцем и
командой проекта. В первый публичный релиз локализация UI не входит: отдельный
словарь строк и система переводов потребовали бы правок в обоих фронтендах и
в админ-API-контракте, а английские надписи уже совпадают с тем, что
пользователь видит в `README.md` и в `docs/INSTALL.md`.
