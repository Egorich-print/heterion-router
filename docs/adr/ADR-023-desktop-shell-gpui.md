# ADR-023 — десктоп-оболочка: Tauri v2 → GPUI

Дата: 2026-11-09 · Статус: принято (реализуется в рабочем дереве).

## Контекст

Настольная оболочка была Tauri v2: окно с WebView, внутри которого шёл тот
же Svelte-бандл, что отдаёт шлюз (ADR-002, ADR-007). Это работало, но
закрывало нативный слой целиком:

- интерфейс дублировался: одни и те же представления живут в
  `desktop/ui/src/views/*.svelte` и рисуются браузером, а не приложением;
- весь интерактив (правка комбо, выдача ключа, playground) уходил в
  JavaScript-слой, хотя те же операции есть в admin-API (`/api/combos`,
  `/api/keys`, `/api/connections`);
- ключ оператора лежал в `localStorage` WebView — то есть в профиле
  браузерного движка, а не в хранилище приложения.

GPUI — фреймворк Zed (`gpui.rs`), на котором написан сам Zed: сцены и
элементы рисуются GPU-конвейером, layout — на taffy, текст — на
cosmic-text. Проверено на этой машине:

| Факт | Значение |
|---|---|
| Крейт | `gpui = "0.2.2"` (crates.io), edition 2024, без капа `rust-version` |
| Сборка | холодная — ~2 минуты на всём дереве зависимостей (arm64, macOS 27.2) |
| Рендерер | без фичи `macos-blade` — собственный Metal-рендерер gpui; шейдеры компилируются на сборке через `xcrun metal` (нужен Xcode) |
| Шрифты | системные macOS: семейство по умолчанию `.SystemUIFont` → `.AppleSystemUIFont`; свои файлы шрифтов не нужны |
| Фичи | `default-features = false, features = ["font-kit"]` — `font-kit` обязателен, без него нет macOS-текст-системы |
| Toolchain | собирается на stable 1.99.0, том же пине, что и остальной workspace |

Проверено на практике: `Application::new().run(...)` поднимает настоящее
окно macOS, `gpui::uniform_list`, `EntityInputHandler` и `FocusHandle`
доступны из публичного API.

## Решение

**Оболочка переезжает на GPUI.** Новый крейт — `desktop/gpui`
(`heterion-router-desktop`), отдельный от быстрого workspace шлюза, как и
прежний `desktop/src-tauri`. `desktop/src-tauri` удаляется.

**Svelte-бандл остаётся.** `desktop/ui` продолжает собираться и раздаётся
шлюзом: это веб-дашборд, им пользуются из браузера и из удалённых машин.
GPUI-оболочка — это нативный десктоп поверх **того же admin-API**, а не
вторая реализация бэкенда.

**Контракт API — один на оба фронтенда.** `desktop/gpui/src/api.rs` содержит
типизированные структуры, побайтово совпадающие с JSON, который отдаёт
`crates/heterion-router-gateway/src/admin.rs`. Ни одна из сторон не имеет
права разойтись с этим контрактом: расхождение — ошибка компиляции на
одной из сторон.

**Живых виджетов в gpui нет.** В крейте нет `Button`, `Input`, `Table`,
`Select`, `Tabs` — только `div` с flex/grid-стилями, `uniform_list`, текст и
изображения. Поэтому `desktop/gpui/src/widgets/` — собственные виджеты,
стилизованные под `desktop/ui/src/app.css`: те же цвета, радиусы, тона
`ok/warn/bad`. Общие виджеты — единственная точка правды по внешнему виду
нативной оболочки.

**Ключ оператора — файл с правами `0600`**, не `localStorage`:
`<data dir>/desktop/operator-key.json`. Каталог `0700`, запись атомарная
(temp + rename), файл не переиспользуется по симлинку. В БД шлюза ключа
оператора нет: `api_keys.key` хранит маркер `hash-only:<id>` (ADR-005).

**Sidecar-контракт сохранён** (ADR-007): в release-сборке оболочка сама
поднимает `heterion-router-gateway` из каталога рядом со своим исполняемым
файлом, на порту `20129` (`HETERION_ROUTER_SIDECAR_PORT` /
`OMNIROUTE_SIDECAR_PORT`), с `HETERION_ROUTER_PARENT_PID` — шлюз сам уходит,
когда родителя нет. В debug-сборке оболочка говорит с уже запущенным шлюзом
(`20128`).

**Упаковка — без Tauri.** `desktop/gpui/packaging/` (`Info.plist`) и
`desktop/scripts/build-app.sh` собирают `Heterion Router.app` с иконками из
прежнего набора, sidecar рядом с бинарём и adhoc-подписью (`codesign -s -`),
как и прежний Tauri-бандл; notarization по-прежнему не выполняется.

**Инструменты для работы с GUI.** Нативное окно нельзя увидеть из агента,поэтому
в `desktop/gpui/tools/` появляются харнесс визуальной проверки (запуск,
скриншот, статус) и MCP-сервер (`desktop/gpui/tools/mcp/server.js`), который
отдаёт агенту живое состояние шлюза и снимок экрана. Факты по API gpui
зафиксированы в `docs/port/GPUI-API-NOTES.md` — читать исходники крейта
каждый раз не нужно.

## Следствия

**Хорошо.** Нативный рендеринг вместо WebView; одна реализация API-контракта;
ключ в файле приложения, а не в профиле браузера; оболочка больше не тащит
ни Node, ни Vite в сборку. Быстрый цикл шлюза (`cargo test --workspace`)
не замедляется: `desktop/gpui` вне workspace, как и был `desktop/src-tauri`.

**Плохо.** Виджеты пришлось писать самим: у gpui их нет, и это основная
цена перехода (текстовое поле с кареткой и выделением — самая дорогая часть).
Сборка десктопа требует Xcode: `xcrun metal` компилирует шейдеры gpui на
этапе сборки крейта. Десктоп остаётся вне быстрого CI-цикла и требует
отдельной проверки (`cargo check --manifest-path desktop/gpui/Cargo.toml`).

**Следствия для кода.** Крейт собирается на Rust 1.99 / edition 2024, как и
workspace. gpui не входит в workspace-зависимости: у него собственный
lock-файл и отдельный target-каталог. Ветка UI-логики живёт в
`desktop/gpui/src/views/`, общие элементы — в `desktop/gpui/src/widgets/`,
контракт — в `desktop/gpui/src/api.rs`; правка `api.rs` обязана идти
вместе с правкой gateway-обработчиков.
